# ADR-0002: Порт правил на TypeScript, Java остаётся эталоном

Дата: 2026-10-30
Статус: принято

## Контекст

Для публикации на Яндекс Играх нужен HTML5-клиент: игра исполняется в
браузере на устройстве игрока, серверной части нет. Движок правил
существует только на Java 21 (`core/`), UI — Swing (`desktop/`) и
консоль (`console/`). Перенести Java-код в браузер можно было через
Kotlin/JS или J2CL, но `core/` использует `sealed interface`, `record`
и `List.getFirst()` — J2CL такое не компилирует без переписывания, а
Kotlin/JS требует перевести Java в Kotlin, то есть того же объёма
переписывания, но с потерей читаемости диффа и с runtime Kotlin в
бандле.

Нормативный документ правил — `RULES.MD` — языко-независим и прямо
предполагает реализацию на любом языке (вводная часть, §16). Объём
правил — около 1200 строк Java.

## Решение

- Правила заново реализуются на TypeScript в `web/src/engine/`,
  источник истины — `RULES.MD`, а не Java-код. Java используется как
  перекрёстная проверка при расхождениях и как источник готовых
  сценариев приёмки.
- Java-модули не удаляются и не меняются: `core/` остаётся эталонной
  реализацией и движком десктоп-клиента. Дублирование правил —
  осознанная цена за нативный для браузера стек без runtime-прослойки.
- Равенство поведений доказывается тремя механизмами: 24 сценария
  `RULES.MD` §16 в TS-тестах в том же порядке, фаззинг инвариантов §13
  на десятках тысяч seeded-партий, golden round-trip сохранения с
  форматом, совместимым с `GameStateSerializer`.
- Архитектурные инварианты `core/` переносятся как есть, потому что они
  уже верны: единственный путь применения хода (`applyMove`),
  единственный интерфейс выбора (`MoveSelector`), `Move` = `Step` |
  `Place`, события как единственный канал «что произошло», учёт кубиков
  и очередь — в сессии, не в UI (см. ADR-0001).

## Последствия

- Любое изменение правил требует двух реализаций и двух наборов тестов.
  Компенсация: расхождение ловится фаззингом и дифференциальной
  сверкой с JVM перед релизом; правила меняются редко.
- Формат сохранения должен остаться совместимым по именам полей, иначе
  десктопный сейв перестанет читаться в вебе. Это проверяется
  golden-тестом, а не соглашением.
- Веб-клиент не зависит от Gradle и JVM: отдельный npm-модуль `web/`,
  своя сборка, свой тест-раннер, правило сборки запрещает движку
  импортировать рендер, платформу и UI.

## Отложено (не блокирует)

- Дифференциальная сверка Java↔TS в CI: требует JVM в пайплайне веба,
  поэтому запускается вручную на релизных кандидатах.
- Кодогенерация сценариев приёмки из `RULES.MD` — пока сценарии
  переносятся вручную, дословно.
